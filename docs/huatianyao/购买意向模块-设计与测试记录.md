### 1.3 关键设计决策

1. **口令码安全**：明文口令码只在 `POST /api/intents` 响应中出现一次，落库仅存 SHA-256 哈希；`code_hash` 建唯一索引，生成时先查重、冲突重试（≤8 次）+ 索引兜底并发。
2. **口令码字符集**：`A-H J-N P-Z 2-9`（剔除 I/O/0/1），与前端 `common.js` 的 `CODE_PATTERN` 完全一致。
3. **排队位次**：不存储 position，每次按「同商品 WAITING 意向按 submittedAt,id 正序」实时计算序号。撤销后其余位次自动前移、修改不影响位次天然满足，无需迁移数据。
4. **意向与商品解耦**：Intent 只存 `productId`，不建 JPA 关联，避免与商品模块（李婉婷/周琳皓）的实体耦合。
5. **提交意向的商品校验**：无 ON_SALE/FROZEN 商品 → 400「暂无商品在售」；商品 FROZEN（含手动冻结）→ 400「商品交易中，暂停接收新意向」（按 Wiki 字面规则，与前端 FROZEN 显示"交易中"一致）。
6. **终态不可访问**：已成功/失败/撤销的意向，查询、修改、取消一律 404「口令码无效或已失效」；格式非法（长度≠8）同样 404。

### 1.4 提供给组员的内部协作方法（`IntentService`）

| 方法 | 使用方 | 场景 |
|---|---|---|
| `activeQueue(productId)` | 李宇轩 `GET /api/seller/overview` | 返回 WAITING+IN_TRADE 队列（正序、带 position、无口令码），直接可作为 `queue[]` |
| `startTrade(productId, intentId)` | 周琳皓 `POST /products/{id}/deal` | 意向不属于该商品→400；非 WAITING→409 |
| `markTraded(intentId)` / `markFailed(intentId)` | 周琳皓 `POST /products/{id}/result` | 单个意向置 TRADED / FAILED |
| `failAllWaiting(productId)` | 周琳皓 result=SUCCESS；已由 `ProductLifecycleListener` 接入下架流程 | 剩余排队意向批量置 FAILED |

### 1.5 意向状态机（与 Wiki《业务流程图》一致）

```
提交 ──▶ WAITING ──卖家选定──▶ IN_TRADE ──成功──▶ TRADED(终态)
          │  │                    └──失败──▶ FAILED(终态)
          │  └──修改(位次不变，仅WAITING)
          └─────买家凭码撤销──▶ CANCELLED(终态)
```

## 二、接口实现与 Wiki 对照

四个接口路径、方法、入参、统一响应体 `{ code, message, data }`、错误码均与 Wiki《接口设计》一致。以下为 Wiki 未明确、由本模块补充约定（**需同步更新 Wiki，请相关同学确认**）：

| # | 事项 | 本实现 | 说明 |
|---|---|---|---|
| 1 | `PUT /api/intents/{code}` 出参 | 复用 GET 的 `{ intent, product }` | Wiki 只定义了入参与校验；返回位次便于前端复用渲染 |
| 2 | `POST /api/intents/{code}/cancel` 出参 | `{ status: "CANCELLED" }` | Wiki 未定义出参 |
| 3 | IN_TRADE 状态下修改意向 | 400「你已进入交易，无法修改信息」 | 业务流程图仅允许"排队中→修改"；文案与撤销文案风格一致 |
| 4 | 格式非法口令码（如长度≠8） | 404「口令码无效或已失效」 | 与"不存在或终态"同一处理，不泄露口令码是否存在 |
| 5 | 口令码存储 | SHA-256 哈希 + 唯一索引 | Wiki 数据模型即 codeHash，本实现明确算法 |

### 3.3 尚未解决 / 待确认的问题

1. **主分支缺主启动类与配置文件**：默认分支（`feature/qiushengjie-frontend`）至今没有 `@SpringBootApplication` 主类与任何配置文件，整个项目跑不起来。本分支本地补了 `ShopApplication.java` + `application.properties` 用于测试（未包含在 PR）。
2. **与周琳皓分支的 Intent 表名不一致**：本分支（及李宇轩上传的骨架）表名为 `intents`，周琳皓分支为 `purchase_intents` 且实体结构略有差异（他含 `finishedAt`/`@Version`，本版含唯一索引与业务方法）。
3. **IN_TRADE 修改意向返回 400 的规则为补充约定**：Wiki 未明确定义，待全组确认后更新《接口设计》。
4. **deal / result / overview 卖家接口尚未合并到默认分支**：测试中通过 `IntentService` 内部方法模拟"卖家选定/标记结果"验证联动逻辑；待周琳皓、李宇轩分支合并后需做一次端到端联调复测。
5. **并发极端场景**：口令码唯一性靠"查重 + 唯一索引"双保险，但未做多线程压测；课程演示规模下风险可忽略。
6. **意向无时效**（Wiki 规则），长时间堆积的 WAITING 意向会保留至商品下架/交易成功，属预期行为。
